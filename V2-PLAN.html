GatePay V2 — Transaction Status System

Implementation plan for transaction lifecycle, notifications, callbacks, and reimbursement tracking

1. Current State

Currently, transactions have a binary state: verifiedAt (null = pending, timestamp = verified). No reimbursed or failed state. Admin clicks "Trigger verify" which calls the callback URL and marks as verified.

Rules:
• Pending → Verified: Admin verifies, callback fires to partner, email sent to client
• Pending → Failed: Admin marks as failed, admin notification sent
• Verified → Reimbursed: Admin marks reimbursed, callback fires to partner, email sent to client. Reimbursement = accumulated client payments sent back to client
• Failed → Pending: Admin can re-open a failed transaction
• Reimbursed: Terminal state, cannot be reversed

3c. Backfill strategy

Run a one-time mutation: if verifiedAt is set → status = "verified", else → status = "pending". Also insert a statusHistory entry for each backfilled transaction.

4. Reimbursement Flow

GatePay collects payments from clients. Reimbursement means sending accumulated payment value back to the client (e.g. refund, payout, settlement).

Reimbursement process

  1. Admin selects verified transaction(s) to reimburse
  2. Admin enters reimbursement details: amount, method, external ref
  3. GatePay calls partner callback with event: "reimbursed"
  4. GatePay sends client email: "Your payment of {amount} has been reimbursed"
  5. Transaction status moves to "reimbursed" (terminal)

updateStatus mutation

export const updateStatus = mutation({
  args: {
    id: v.id("transactions"),
    status: v.union(
      v.literal("verified"),
      v.literal("reimbursed"),
      v.literal("failed"),
      v.literal("pending"),  // for re-open from failed
    ),
    notes: v.optional(v.string()),
    token: v.string(),
  },
  handler: async (ctx, args) => {
    await requireAdmin(ctx, args.token);
    const tx = await ctx.db.get(args.id);
    if (!tx) throw new Error("not_found");

    const now = Date.now();
    const oldStatus = (tx as any).status ?? "pending";

    // Update transaction
    await ctx.db.patch(args.id, {
      status: args.status,
      statusChangedAt: now,
      statusChangedBy: args.token,
      updatedAt: now,
    });

    // Log history
    await ctx.db.insert("statusHistory", {
      transactionId: args.id,
      fromStatus: oldStatus,
      toStatus: args.status,
      changedBy: args.token,
      changedAt: now,
      notes: args.notes,
    });

    // Fire callback if verified or reimbursed
    if (args.status === "verified" || args.status === "reimbursed") {
      await fireCallback(ctx, tx, args.status as "verified" | "reimbursed");
    }

    // Send email
    await sendStatusEmail(ctx, tx, args.status, oldStatus);

    return { ok: true, from: oldStatus, to: args.status };
  },
});

reimburse mutation

export const reimburse = mutation({
  args: {
    id: v.id("transactions"),
    amount: v.number(),
    method: v.string(),
    reimbursementRef: v.optional(v.string()),
    notes: v.optional(v.string()),
    token: v.string(),
  },
  handler: async (ctx, args) => {
    await requireAdmin(ctx, args.token);
    const tx = await ctx.db.get(args.id);
    if (!tx) throw new Error("not_found");
    if ((tx as any).status === "reimbursed") throw new Error("already_reimbursed");

    const now = Date.now();
    const oldStatus = (tx as any).status ?? "pending";

    await ctx.db.patch(args.id, {
      status: "reimbursed",
      statusChangedAt: now,
      statusChangedBy: args.token,
      reimbursedAt: now,
      reimbursedBy: args.token,
      reimbursementAmount: args.amount,
      reimbursementRef: args.reimbursementRef,
      reimbursementMethod: args.method,
      updatedAt: now,
    });

    await ctx.db.insert("statusHistory", {
      transactionId: args.id,
      fromStatus: oldStatus,
      toStatus: "reimbursed",
      changedBy: args.token,
      changedAt: now,
      notes: `Reimbursed ${tx.currency} ${args.amount} via ${args.method}${args.notes ? ` — ${args.notes}` : ""}`,
    });

    // Fire callback with event: "reimbursed"
    await fireCallback(ctx, tx, "reimbursed");

    // Email client
    await sendStatusEmail(ctx, tx, "reimbursed", oldStatus);

    return { ok: true };
  },
});

Flow

  1. Admin logs in → service worker registers → requests notification permission
  2. If granted, browser generates push subscription → stored in pushSubscriptions
  3. When submitPayPayment fires → Convex action sends push to all admin subscriptions
  4. Service worker receives push → shows native notification with transaction details
  5. Click notification → opens /admin/transactions/{id}
